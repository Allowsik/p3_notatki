Pliki, strumienie i zdarzenia w C#

Co to jest Testably? Wyobraź sobie test, który potrzebuje katalogu z jednym pustym plikiem. Test tworzy MockFileSystem i dodaje do niego plik w pamięci. Badana metoda dostaje ten sam system plików. Dzięki temu dokładnie wiesz, co powinna znaleźć, niezależnie od zawartości laptopa.

Trzy różne obiekty. System plików odpowiada na pytanie „gdzie jest plik?”. Strumień pozwala czytać lub zapisywać kolejne bajty. Zdarzenie pozwala obiektowi powiadomić zainteresowane metody, że coś zaszło.

1. Dysk w pamięci

Jak przeczytać pierwszy wiersz notatki?

Test tworzy własny mały dysk. Zmienna fs wskazuje ten dysk. Ścieżka jest tylko napisem. O tym, gdzie szukasz pliku, decyduje obiekt, na którym wywołasz OpenRead. W projekcie konsolowym do tego przykładu dodaj pakiet Testably.Abstractions.Testing i using Testably.Abstractions.Testing;. Pozostałe przykłady korzystają ze standardowych przestrzeni System, System.IO, System.Linq i System.Collections.Generic.

Pokaż kod i prześledź wynik
var fs = new MockFileSystem();
string path = fs.Path.Combine(fs.Directory.GetCurrentDirectory(), "plan.txt");
fs.File.WriteAllText(path, "Intro\nSolo");

using var stream = fs.File.OpenRead(path);
using var reader = new StreamReader(stream);
Console.WriteLine(reader.ReadLine());

Intro. OpenRead otwiera bajty, a StreamReader zamienia je w tekst. Drugie ReadLine() da Solo, trzecie zwróci null. Jeśli zadanie już przekazuje fs do metody, użyj tego obiektu. Nowy MockFileSystem miałby własne pliki.

2. Metoda do przetestowania

Jak policzyć bajty zarówno na dysku, jak i w pamięci?

Podziel pracę w miejscu, gdzie otwierasz plik. Kod poniżej dostaje już otwarty strumień. Możesz podać fs.File.OpenRead(path) lub zbudować mały przykład bez pliku.

Pokaż kod i prześledź wynik
static int CountZeros(Stream input)
{
    int zeros = 0;
    int value;
    while ((value = input.ReadByte()) != -1)
        if (value == 0) zeros++;
    return zeros;
}

using var sample = new MemoryStream(new byte[] { 0, 8, 0 });
Console.WriteLine(CountZeros(sample));

2. ReadByte zwraca int, dzięki czemu -1 oznacza koniec, a 0 jest poprawną daną. Ponowne wywołanie na tym samym strumieniu da 0, bo kursor jest już na końcu. Strumień zamyka kod, który go utworzył.

3. Bufor i częściowy odczyt

Skopiuj pięć bajtów buforem o długości trzy.

Read zwraca liczbę bajtów rzeczywiście wpisanych do tablicy. Przy ostatnim przejściu część bufora może nadal zawierać dane z poprzedniego obrotu.

Pokaż kod i prześledź wynik
using var src = new MemoryStream(new byte[] { 1, 2, 3, 4, 5 });
using var dst = new MemoryStream();
byte[] buffer = new byte[3];
int n;
while ((n = src.Read(buffer, 0, buffer.Length)) > 0)
    dst.Write(buffer, 0, n);
Console.WriteLine(string.Join(",", dst.ToArray()));

1,2,3,4,5. Pierwszy odczyt daje 3, drugi daje 2. Write z buffer.Length dopisałby stare 3. Gdy niczego nie zmieniasz po drodze, całą pętlę zastępuje src.CopyTo(dst). Żeby potem czytać z dst, ustaw dst.Position = 0.

4. Dekorator odczytu

Jak policzyć przeczytane bajty bez zmieniania kodu, który czyta?

Dekorator sam jest strumieniem i przechowuje drugi strumień w polu inner. Gdy klient woła Read, dekorator przekazuje wywołanie do środka, zapamiętuje wynik i oddaje go klientowi. Oto pełny wariant tylko do odczytu. Strumień wewnętrzny pozostaje własnością wywołującego.

Pokaż kod i prześledź wynik
sealed class ReadMeter : Stream
{
    private readonly Stream inner;
    public long Total { get; private set; }
    public ReadMeter(Stream inner) => this.inner = inner;

    public override int Read(byte[] buffer, int offset, int count)
    {
        int n = inner.Read(buffer, offset, count);
        Total += n;
        return n;
    }

    public override bool CanRead => inner.CanRead;
    public override bool CanWrite => false;
    public override bool CanSeek => false;
    public override void Flush() { }
    public override long Length => throw new NotSupportedException();
    public override long Position
    {
        get => throw new NotSupportedException();
        set => throw new NotSupportedException();
    }
    public override long Seek(long offset, SeekOrigin origin)
        => throw new NotSupportedException();
    public override void SetLength(long value)
        => throw new NotSupportedException();
    public override void Write(byte[] buffer, int offset, int count)
        => throw new NotSupportedException();
}

Próba: opakuj MemoryStream z bajtami 10, 20. Wywołaj Read(buffer, 1, 4) na buforze pięcioelementowym pełnym zer. Dostaniesz [0,10,20,0,0], wynik 2 i Total równe 2. Offset określa miejsce w tablicy odbiorcy. Jeżeli modyfikujesz dane po odczycie, przejdź po indeksach od offset do offset + n, bez ostatniej granicy.

5. Własne zdarzenie

Jak powiadomić ekran, że zakończyło się nagranie?

Rejestrator decyduje, kiedy nagranie się skończyło. Ekran decyduje, co wtedy pokazać. Łączysz je operatorem +=. EventArgs.Empty wystarcza, kiedy sama wiadomość o zakończeniu mówi odbiorcy wszystko.

Pokaż kod i prześledź wynik
var recorder = new Recorder();
recorder.Finished += Display;
recorder.Stop();
recorder.Finished -= Display;
recorder.Stop();

static void Display(object? sender, EventArgs e)
    => Console.WriteLine("Zapisano");

sealed class Recorder
{
    public event EventHandler? Finished;
    public void Stop() => Finished?.Invoke(this, EventArgs.Empty);
}

Zapisano pojawi się raz. Pierwszy Stop wywołuje metodę Display. Po -= lista odbiorców jest pusta, a ?. pozwala bezpiecznie pominąć wywołanie. Display bez nawiasów oznacza przekazanie metody do późniejszego użycia.

6. Zdarzenie z danymi

Podaj odbiorcy poziom dźwięku przy przekroczeniu progu.

Zapisz poprzedni poziom. Dla kolejnych wartości 70, 82, 85 tylko przejście 70 → 82 przekracza próg 80. Dane przekazujesz jako drugi argument Invoke.

Pokaż kod i prześledź wynik
sealed class LevelArgs : EventArgs
{
    public int Level { get; }
    public LevelArgs(int level) => Level = level;
}

sealed class Meter
{
    private int previous;
    public event EventHandler<LevelArgs>? Peak;

    public void Update(int level)
    {
        bool crossed = previous < 80 && level >= 80;
        previous = level;
        if (crossed) Peak?.Invoke(this, new LevelArgs(level));
    }
}

Podłącz meter.Peak += (_, e) => Console.WriteLine(e.Level); i wywołaj Update kolejno dla 70, 82, 85, 40, 80. Zobaczysz 82 i 80. Podkreślenie oznacza tu pominięty argument nadawcy. Do późniejszego odpięcia lambdy zachowaj ją w zmiennej typu EventHandler<LevelArgs>.

7. Ścieżki i metadane

Jak wybrać rozszerzenie i rozmiar pliku?

Zakładając fs i path z pierwszego przykładu, Path rozkłada nazwę na części, File czyta zawartość, a FileInfo daje dostęp do metadanych. Rozmiar mierzysz w bajtach.

Pokaż kod i prześledź wynik
string name = fs.Path.GetFileName(path);
string ext = fs.Path.GetExtension(path);
long bytes = fs.FileInfo.New(path).Length;
bool isText = string.Equals(ext, ".txt",
                            StringComparison.OrdinalIgnoreCase);
Console.WriteLine($"{name} {isText}");

plan.txt True. GetExtension zwraca kropkę razem z rozszerzeniem. Path.Combine(root, "takes", "intro.txt") składa ścieżkę z elementów. Przy kopiowaniu do nowego podkatalogu najpierw utwórz go przez fs.Directory.CreateDirectory.

8. Filtry katalogu

Znajdź w całym drzewie pliki spełniające wszystkie przekazane reguły.

Rozbij zadanie na dwa pytania. Skąd biorę kandydatów? Których kandydatów zwracam? Func<string, bool> oznacza funkcję, która dostaje ścieżkę i daje odpowiedź tak lub nie.

Pokaż kod i prześledź wynik
static IEnumerable<string> Filter(IEnumerable<string> paths,
                                  params Func<string, bool>[] rules)
{
    foreach (string path in paths)
        if (rules.All(rule => rule(path)))
            yield return path;
}

var paths = fs.Directory.EnumerateFiles(root, "*",
                                        SearchOption.AllDirectories);
var found = Filter(paths,
    p => fs.Path.GetExtension(p).Equals(".txt", StringComparison.OrdinalIgnoreCase),
    p => fs.FileInfo.New(p).Length > 0);
foreach (var p in found) Console.WriteLine(p);

Próba: w root umieść pusty a.txt i b.wav, a w podfolderze niepusty c.TXT. Przejdzie tylko c.TXT. Bez reguł All zwraca true. Any sprawdza, czy przechodzi choć jedna reguła. yield return oddaje jeden wynik i pozwala wznowić pętlę przy następnym kroku foreach.

9. Test odbiorcy

Jak udowodnić, że powiadomienie przyszło dokładnie raz i z dobrymi danymi?

Użyj Meter z wcześniejszej karty. Zamiast wypisywać na konsolę, odbiorca może zbierać wartości w liście. Na końcu porównasz całą historię z oczekiwaną.

Pokaż kod i prześledź wynik
var meter = new Meter();
var seen = new List<int>();
EventHandler<LevelArgs> collect = (_, e) => seen.Add(e.Level);
meter.Peak += collect;
meter.Update(79);
meter.Update(80);
meter.Update(95);
meter.Peak -= collect;
meter.Update(0);
meter.Update(99);
Console.WriteLine(seen.SequenceEqual(new[] { 80 }));

True. Ten jeden przebieg sprawdza dokładny próg, kolejne wysokie wskazanie i odpięcie odbiorcy. Zmiana >= na > lub pominięcie -= zmieni wynik testu.

10. Nowy eksport w katalogu roboczym

Jak odświeżyć listę, gdy edytor dodaje plik?

EnumerateFiles daje listę podczas przeglądania katalogu. FileSystemWatcher wysyła zdarzenia o późniejszych zmianach. W tej próbie program tworzy własny katalog tymczasowy i sam zapisuje w nim plik.

Pokaż próbę
var folder = Directory.CreateTempSubdirectory();
try
{
    using var watcher = new FileSystemWatcher(folder.FullName, "*.txt");
    using var arrived = new System.Threading.ManualResetEventSlim();
    watcher.Created += (_, e) => {
        if (e.Name == "take.txt") arrived.Set();
    };
    watcher.EnableRaisingEvents = true;
    File.WriteAllText(Path.Combine(folder.FullName, "take.txt"), "intro");
    Console.WriteLine(arrived.Wait(TimeSpan.FromSeconds(3)));
}
finally
{
    folder.Delete(recursive: true);
}

Oczekiwany wynik to True. Najpierw podpinamy odbiorcę, potem włączamy obserwację i dopiero tworzymy plik. Wait daje odbiorcy czas na reakcję. Powiadomienie Created oznacza pojawienie się nazwy. Zapis treści może jeszcze trwać.

Wariant. Przy zmianie nazwy podepnij Renamed. Argument zdarzenia udostępnia OldName i Name. Przy modyfikacji zawartości służy Changed. Jeden zapis może wywołać kilka powiadomień.

11. Postęp odczytu

Jak pokazać liczbę przetworzonych bajtów po każdej porcji?

W klasie ReadMeter z ćwiczenia 4 dodaj zdarzenie, a metodę Read zastąp poniższą wersją. Licznik pamięta sumę od początku. Zdarzenie daje ekranowi okazję, żeby tę sumę odczytać.

Pokaż zmianę w klasie
public event EventHandler? Progress;

public override int Read(byte[] buffer, int offset, int count)
{
    int n = inner.Read(buffer, offset, count);
    Total += n;
    if (n > 0) Progress?.Invoke(this, EventArgs.Empty);
    return n;
}

Próba z pięcioma bajtami i dwuelementowym buforem:

using var source = new MemoryStream(new byte[] { 1, 2, 3, 4, 5 });
using var meter = new ReadMeter(source);
meter.Progress += (_, _) => Console.WriteLine(meter.Total);
byte[] block = new byte[2];
while (meter.Read(block, 0, block.Length) > 0) { }

Na ekranie pojawią się kolejno 2, 4 i 5. Ostatnie wywołanie Read zwraca zero. Warunek n > 0 zapobiega ponownemu wypisaniu 5 po dojściu do końca.
